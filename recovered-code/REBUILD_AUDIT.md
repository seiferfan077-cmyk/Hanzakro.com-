# جرد استعادة منصة هنذاكروا

## الوضع الحالي

هذا الفرع (`manus/recovered-code-artifacts`) يحتوي مواد مسترجعة من مرفقات مهمة قديمة، وليس شجرة المشروع الأصلية. جُمعت الملفات داخل مجلد معزول لأن مساراتها الأصلية غير موجودة في سجل المرفقات. جذر المستودع `main` كان يحتوي README فقط؛ لا توجد نسخة تطبيق كاملة يمكن تشغيلها أو عرضها حاليًا.

من المواد المسترجعة: 103 ملف TypeScript/TSX (بعضها اختبارات، وبعضها وحدات تطبيق/خادم)، و24 ملف SQL بأسماء تسلسلية من 0060 إلى 0083. لم تُشغّل الاختبارات أو ملفات SQL، ولم يُجرَ نشر.

## ملامح المنصة المستنتجة من الكود

- صفحات ومكوّنات للدراسة والمفردات والمراسلة الخاصة.
- قسم مسابقات وغرف امتحان، ومساعد تعليمي باسم لؤي، وبحث ومصادر ويب.
- مشاركة مواقع وحضور، نوافذ عائمة، فيديوهات تعليمية، ومنصات/أقسام.
- خلفية تستخدم مفاهيم Drizzle وقاعدة بيانات، tRPC، ومكوّنات React؛ تظهر كذلك إحالات إلى Firebase وGoogle Drive وتخزين ملفات وLLM.

هذه ملاحظات عن الاستيرادات الموجودة، وليست تأكيدًا بأن جميع الخدمات ما زالت مستخدمة أو مضبوطة في النسخة المقصودة.

## موانع البناء الحالية

لا توجد في الفرع ملفات التشغيل والتجميع الأساسية التالية:

- `package.json` وملف قفل الحزم.
- `index.html` ومدخل الواجهة مثل `client/src/main.tsx` و`client/src/App.tsx`.
- إعداد Vite وTypeScript، ومسارات React الفعلية، وملفات CSS/الأصول.
- بنية مجلدات `client/` و`server/` و`drizzle/` الأصلية.
- تعريف قاعدة البيانات الكامل ومخطط Drizzle وسجل الترحيلات الأقدم من 0060.
- إعداد الخادم وtRPC والسياق والمصادقة والموجّهات.
- وحدات مشتركة وملفات هوية ومساحات العمل والتخزين والمزودات الخارجية.
- متغيرات البيئة والتوثيق الآمن لها (لا ينبغي وضع أسرار فعلية في Git).
- إعدادات Vercel أو معلومات مشروع منشور مرتبطة بهذا المستودع.

## استيرادات داخلية مطلوبة ظهرت في المواد

ضمن المجموعة المسترجعة، بقيت إحالات إلى وحدات غير موجودة في المجلد، منها:

`../drizzle/schema`, `GeneralFloatingBar`, `ImageResult.js`, `InfoResult.js`, `LoadParameters.js`, `ParseParameters.js`, `PlatformSectionsBar`, `ScreenshotResult.js`, `TableResult.js`, `TextResult.js`, `_core/context`, `_core/llm`, `db`, `firebaseAdmin`, `googleDrive`, `groq`, `pdfIndex`, `presence`, `privateMedia`, `routers`, `storage`, `studyAssistant`, `workspaceAccess`, `workspaceContentDb`, `workspaceIdentity`.

بعض الإحالات قد تكون لمكتبات/ملفات خارجية في النسخة الأصلية أو لمسارات تغيّرت؛ يلزم استعادة السياق الأصلي قبل إعادة كتابة البدائل.

## خطة إعادة البناء المقترحة

1. العثور على نسخة مرجعية حقيقية: رابط المنصة الحالية إن كانت منشورة، أو ZIP/نسخة المشروع الأصلية/فرع آخر. هذا يسمح بمقارنة الملفات بدل اختراع بنية قد لا تطابق التطبيق.
2. تثبيت قرارات التقنية والهيكل. الاستيرادات توحي بـ React + Vite مع tRPC/Drizzle، لكن لا تكفي لتحديد إصدار الحزم أو شكل الخادم.
3. إنشاء أساس قابل للتشغيل أولًا: إعدادات الحزم والبناء، نقطة دخول الواجهة، التوجيه، التصميم الأساسي، الخادم، قاعدة البيانات، واختبار تشغيل أولي.
4. إعادة الوحدات المسترجعة إلى مجلداتها المناسبة وربطها تدريجيًا، مع اختبار كل دفعة.
5. استكمال الخدمات الخارجية عبر متغيرات بيئة آمنة، ثم إعداد Vercel ونشر معاينة بعد موافقة المستخدم.

## ما لم يحدث

لم يُنشأ تطبيق بديل، ولم تُنقل ملفات بيانات اعتماد، ولم يُطبّق أي ترحيل قاعدة بيانات، ولم يُنشأ مشروع Vercel أو نطاق. هذا التقرير جرد أولي مبني على المواد المتاحة في الفرع فقط.
